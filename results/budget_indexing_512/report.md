# LongVul 预算感知索引与任务适配编码

## 实验协议

对照来自 `31349ae` 的 Predicted Fusion 和匹配 Oracle Fusion。所有新组固定 32 BPE 分块、块内均值、四头 128 维 QK、中心优先检索、原语法关系排序、96 位置上下文预算和 512 位置精细编码。精细分类保持标准 UniXcoder 注意力及 Global Fusion。匹配 Oracle 的 Test 输入依赖真实修复 Diff，仅用于特权诊断。

- **Retrieval Selection** 沿用 BCE + KL，索引器选取完整 Valid 检索后原始 UniXcoder >510 BPE 函数的实际修改 BPE 保留率最高的一轮。分母为原始修改 BPE 数，完全遗漏率单独统计，空侧邻近代理不计入选模分子或分母。
- **Budget Ranking** 保留同一 BCE，使用排名实际选中的中心块确定成对排序对象。被遗漏的有修复标注块以修复 BPE 质量加权，和所有已入选的无标注块比较。选块用四头平均概率，损失用该概率的对数，取对数前使用 `1e-12` 数值下限。每个参与函数先独立按负块数和遗漏修复质量归一化，再按函数取均值。未形成有效比较的函数继续参与 BCE。短函数完整可见，不产生预算排序监督。
- **Adapted Encoding** 先按 Seed 42 的同一 Valid 保留率在 KL 和预算排序间选监督。从预训练 UniXcoder 开始，仅训练最后两层，嵌入及前十层固定。完整函数使用原非重叠窗口，分批计算并通过激活检查点反传。精细训练期间固定粗编码器与索引器。
- **Adapted Index + Frozen Fusion** 与 Adapted Encoding 共享适配索引和精细选段，仅将直接参与分类融合的全局表示换为原始冻结 UniXcoder 的表示。精细分类器独立训练。Test 计入两次完整函数窗口编码。
- **Joint Supervision** 冻结 UniXcoder，使用 BCE + 1.0 KL + 0.1 Ranking。按相同 Valid 检索指标选模。若超过单独 KL，再进行相同最后两层适配和匹配 Fusion 诊断。记录相同 Train 批次上初始化与入选检查点的单项损失、Q/K 梯度范数及加权梯度范数。

每个种子的全局辅助头和 Q/K 都在本轮重新初始化和训练。冻结编码组共享未微调的预训练块缓存。精细分类器各自从预训练 UniXcoder 初始化，用 FP32 Eager、16 轮、batch 8、AdamW、学习率 2e-5 和 10% warmup。精细检查点按完整 Valid MCC 选择，并列时取最早轮。Test 判定固定为 `p > 0.5`。样本及配对使用原始 PrimeVul 划分及统一的 CodeBERT 长度口径。Test 的修复标注在新组完成检索和分类后用于计算诊断指标。

预算内修复块召回率以所有含实际修改 BPE 的压缩后代码块为分母。全块覆盖是主口径，与至少有一个 BPE 可见的召回率一同保存。块级 AP 采用实际修改相关块作为正类。

在 `01e0479` 的基础上，补齐 Adapted Encoding 和 Adapted Index + Frozen Fusion 的 Seed 1234、123456。两个补充种子沿用已训练的对应辅助头，各从原始预训练 UniXcoder 开始重新训练一次 BCE + KL 任务适配索引器，选定的检查点供两组精细分类共享。两种 Fusion 方式各自独立训练 16 轮。两个种子在同一主机的两张 RTX 4090 上并行，每个进程单卡。

## 验证

61 项单元测试覆盖实际中心选块、按函数归一化、联合损失及参数梯度。真实 RTX 4090 检查处理原始 231,660 和 232,766 BPE 的函数，并完成带预算排序监督的反向传播。Q/K 与最后两层获得非零梯度并更新，冻结层无梯度，两份精细输入均为 512 位置。[GPU 记录](smoke.json)

## 索引器 Valid 选模

Seed 42 的 BCE + KL 索引训练与历史训练逐轮一致。辅助 MCC 选择第 6 轮，其原始 UniXcoder 长组修改 BPE 保留率为 45.38%，完全遗漏率为 23.43%。检索选模选中第 12 轮，保留率为 45.88%，完全遗漏率为 22.24%。在 589 个有实际修改的长函数中，完全遗漏从 138 个降到 131 个。仅改索引选模的精细分类器在 Test 的整体 MCC 从 0.0941 降到 0.0762，长函数修改 BPE 保留率从 48.25% 升到 48.58%。

预算排序的最佳 Valid 检索轮为第 8 轮，长组保留率为 43.17%，完全遗漏率为 27.33%。任务适配编码按这项预定指标沿用 KL。[KL 逐轮记录](seed42/retrieval_selection/index/epochs.json) · [预算排序逐轮记录](seed42/budget_ranking/index/epochs.json)

任务适配的 KL 索引在第 3 轮达到最佳 Valid 保留率 48.05%，完全遗漏率 19.35%。冻结和适配 Fusion 的 Seed 42 精细输入位置在 Valid 的 1,124 个函数和 Test 的 1,128 个函数上逐样本一致。保留原始冻结 Fusion 时，整体 Test MCC 从 0.1169 升至 0.1419，UniXcoder 长组从 0.0944 升至 0.1501。匹配对照的增益来自融合表示及其与独立训练的交互，两个组在检索方面没有差异。[Adapted Encoding](seed42/adapted_encoding/fine/metrics.json) · [Matched Frozen Fusion](seed42/adapted_index_frozen_fusion/fine/metrics.json)

冻结编码器的联合监督选中第 9 轮，Valid 长组修改 BPE 保留率为 46.06%，完全遗漏率为 21.39%。保留率比单独 KL 高 0.18 个百分点，满足预定的后两层适配条件。

## 结论

联合监督相对原 LongVul 的整体 MCC 差值为 +0.0279、−0.0269 和 −0.0537，平均下降 0.0176。联合监督仅略微缩小检索保留率差距，和 Oracle 的整体 MCC 差距反而从 0.0906 扩大到 0.1082。直接按检索质量选模和只用预算排序在 Seed 42 都未改善长组检测。最后两层适配提升了该种子的检索保留率，但增加了索引训练成本，两种融合诊断也没有给出一致结果。原 LongVul 保留为正式配置。

## BCE + KL 适配补充种子

适配索引器在 Seed 42、1234、123456 分别选择第 3、5、4 轮，Valid 长组修改 BPE 保留率分别为 48.05%、46.24%、46.97%。三个种子均验证了共用索引轮次、Valid 的 1,124 个精细检索布局和 Test 的 1,128 个精细检索布局。补充种子的配置文件除种子值和由训练产生的索引轮次外，与 Seed 42 一致。四个精细分类训练都完成了 16 轮。[Seed 1234](seed1234/) · [Seed 123456](seed123456/) · [完整布局核对](summary.json)

Frozen Fusion 相对 Adapted Encoding 的整体 Test MCC 差值依次为 +0.0250、−0.0182、+0.0174，平均 +0.0081，种子间波动也增大。两种适配方式的整体和 CodeBERT 长组 MCC 均值均低于原 LongVul。Frozen Fusion 的 CodeBERT 超长组均值为 0.0552，较原 LongVul 高 0.0054，只有 Seed 42 高于对应的原模型。按 UniXcoder 的超长组划分，Frozen Fusion 为 0.0381，原 LongVul 为 0.0626。Frozen Fusion 的整体 ROC-AUC 和配对排序准确率分别达到 0.5705 和 59.69%，F1 为 0.5048，低于原 LongVul 的 0.5537。固定阈值的检测结果与排序指标反映的变化不同。

共享适配索引使 UniXcoder 长组修改 BPE 保留率提高 0.69 个百分点，超长组提高 1.69 个百分点。长组完全遗漏率从 22.84% 升到 26.17%，块 AP 从 0.1546 降到 0.1396。保留率的小幅提高与更高的完全遗漏同时出现。长组和超长组保留率仍距匹配 Oracle 36.41 和 54.76 个百分点。两种适配的整体 MCC 均值略高于三个外部基线均值，当前三种子的波动仍影响比较。原 LongVul 继续作为正式配置。
