# LongVul 细粒度索引对照

## 研究问题与固定条件

B0 对 32 BPE 的平均块向量归一化再做 QK 匹配。B1 先对各有效 Token 归一化并匹配，再取块内分数均值。B2 使用同一 Token 匹配计算，对块内分数取 LogMeanExp。B1 在线性 Key 投影下等价于匹配归一化 Token 表示的均值，控制归一化发生在何处。B2 额外测试高分 Token 能否提高其所在块的检索价值。减去有效块长的对数可消除分数相同时的块长偏好。

ColBERT 在检索时保留细粒度匹配，Quest 根据查询评估缓存页。本实验把匹配单元与检索单元分开，并以函数级 BCE 和历史块级修复 KL 训练索引器。[ColBERT](https://arxiv.org/abs/2004.12832) · [Quest](https://proceedings.mlr.press/v235/tang24l.html)

所有索引器使用四个查询头和 128 维索引空间。每种子重新训练全局辅助头 16 轮。随后从该头及相同种子下新初始化的 Q/K 出发训练 16 轮 BCE + KL，修复权重为 1。三个 Seed 42 精细分类器独立训练 16 轮。从下游 Valid MCC 较高的 Token 匹配组及 B0 执行两个补充种子。全局分支为原始预训练 UniXcoder 的冻结非重叠窗口编码，局部 Token 只获得所在窗口的上下文。最终分类仍使用原始源码、32 BPE 中心块、96 位置关联上下文、512 位置精细预算和 Global Fusion。精细训练沿用 FP32 Eager、batch 8、学习率 2e-5、AdamW 和 10% 预热。选模使用完整 Valid MCC，测试判定为 `p > 0.5`。Test 在选段和预测后才参与 Diff 诊断。

低密度块比较限定为完整 32 BPE 块和实际需要选段的函数，再按两种原始 BPE 长度分组。修改量是历史行级 Diff 覆盖的实际修改 BPE，空侧邻近标签单独统计。该统计同时报告同一函数中的零修改块入选率。零修改块也可能包含判别信息，移入更多这类块只能说明检索的修复相关性变化。小修改配对按两侧行级 Diff BPE 总数归组，长度按配对两侧较长函数归组。

## 计算成本

Train 和 Valid 共缓存 16,101,581 个有效 Token、24.73 GB。写入采用 BF16 冻结编码和 FP16 存储。联合生成的两份块缓存与历史块向量逐值相等。全局编码与写入合计约 537 秒，加入映射创建、刷盘和缓存比对后约 550 秒，源文件分词在各次训练的准备时间中另记。训练和推理逐批读取 Token，只有有效块及每个函数末块的 padding 会进入匹配张量。[缓存成本](token_cache.json)

三组 Test 均执行 4,432 个全局窗口和 1,128 个精细输入，合计处理 2,432,962 个有效位置。Seed 42 的 Index / Test 端到端耗时分别为 B0 0.52 / 34.54 秒、B1 2.45 / 41.86 秒、B2 2.42 / 40.18 秒。峰值推理显存为 1.11 / 1.39 / 1.39 GiB。Token 实验端到端计时包含实时全局编码和临时约 2.98 GB 的 Test 主存表示，未读取 Test Token 磁盘缓存。Seed 42 索引训练共用的全局头耗时单列，联合索引训练分别为 209 / 542 / 430 秒，其中 B1 首轮 139 秒，后续大多约 26 秒。[各阶段配置、逐轮耗时与预测](seed42/)

三种子平均端到端耗时为 B0 34.86 秒、B1 40.50 秒。联合索引训练平均为 192 秒和 463 秒，峰值 GPU 内存平均为 0.53 GiB 和 2.02 GiB。精细训练分别约 35.87 分钟和 35.66 分钟。另有各种子共用的全局辅助头训练成本。所有成本来自实际记录，训练时间是否包含冷缓存读盘由该次运行实际发生的 I/O 决定。[三种子成本](summary.json)

## 原始数据中的两个动机案例

两例均来自原始 Valid 配对，通过原始数据中的提交和函数正文对齐，按修复性质与源码距离筛选。BPE 区间以零为起点、右端不含，源码行号按函数自身从 1 计数。

- **少量 Token 改变安全语义。** LibVNCServer 的 `rfbScaledScreenUpdateRect`（CVE-2020-14401，`primevul_paired:valid:192`）修复前后分别为 1,516 和 1,519 个原始 UniXcoder BPE。第 79 行的补丁在像素运算的移位前拓宽操作数类型，避免中间结果按较窄类型运算。字符级改动覆盖修复版的 4 个 BPE `[1020,1024)`，历史行级监督分别覆盖 `[1015,1034)` 与 `[1015,1037)`。这个差异已经超出固定 Head 的可见范围，并且占函数正文很小一部分。[LibVNCServer 修复](https://github.com/LibVNC/libvncserver/commit/a6788d1da719ae006605b78d22f5a9f170b423af) · [CVE 记录](https://nvd.nist.gov/vuln/detail/CVE-2020-14401)
- **安全语义跨越多个区域。** Linux 的 `tpacket_rcv`（CVE-2020-14386，`primevul_paired:valid:231`）修复前后分别为 3,062 和 3,106 个原始 BPE。修复拓宽接收路径偏移量的声明类型，并在后续路径加入边界检查。修复前，第 12 行声明位于 `[123,135)`，第 68–69 行的偏移计算位于 `[701,732)`，两者相隔 566 个原始 BPE，Simple 压缩后仍相隔 547 个正文 BPE。修复版新增检查的行级修改区间为 `[852,892)`。只看到偏移表达式无法核实计算结果经过何种类型转换及何时检查边界。[Linux 修复](https://git.kernel.org/pub/scm/linux/kernel/git/torvalds/linux.git/commit/?id=acf69c946233259ab4d64f8869d4037a198c7f06) · [Ubuntu 安全公告及提交映射](https://ubuntu.com/security/CVE-2020-14386#patch-details)
