# LongVul 全局融合消融与匹配 Oracle

## 对照协议

Predicted Fusion 沿用 `a87c8a1` 中与仓库主实验 LongVul 逐样本一致的三个种子。Predicted Fine-only 保留该提交的 Seed 42，补齐 Seed 1234 和 123456。每个种子使用关系编码实验训练的共享索引器，本轮各新训练的精细分类器均从原始预训练 UniXcoder 开始。

Oracle 是在 Train、Valid、Test 读取真实修复配对的特权诊断。它使用索引器训练时的同侧修复分布替换预测块分数。计算采用实际修改 BPE 和历史空侧邻近区域的并集，按各 32 BPE 块中覆盖的 BPE 数归一化。无有效修复标注的函数保留全零分数。零分和同分块沿用常规的稳定降序和源码顺序。报告分别记录零分块、正分并列和全零函数。其余检索行为均沿用中心优先选择、原语法关系排序、96 位置上下文预算、按块分数填充及 512 位置精细输入打包。

两种排名使用相同的当前函数冻结表示。Oracle 仍执行同一块级索引打分，随后只替换用于精细检索的分数，融合向量保留计算自当前函数的 Mean/Max。Fine-only 的最终分类只读取精细 CLS。Oracle 的两个融合设置各自独立训练。

精细训练采用 FP32 Eager、16 轮、batch 8、学习率 2e-5、AdamW 和 10% 线性预热。沿用原始 PrimeVul 配对划分的 8,708 / 1,124 / 1,128 个函数，以完整 Valid MCC 选择检查点，分类阈值统一为 `p > 0.5`。两种长度分层使用原始正文 BPE，配对组按两侧较长的函数长度确定。

实际修改 BPE 保留和完全遗漏的分母排除空侧邻近代理，完全遗漏率只统计具有实际修改 BPE 的函数。关联上下文比较限定为两种排名均完整保留来源语句、该语句与至少一组已选块相交、关系两端可共同放入精细预算的语法关系。由此每对排名有共同分母。当前 Oracle 检验在这套块级预算和分类器上的修复信息价值。它的输入依赖待预测函数的真实修复版本。

## 复现检查

58 项单元测试通过。RTX 4090 smoke test 对原始 231,660 和 232,766 BPE 的真实修复对完整进行冻结多窗口编码，精细输入均为 512 位置。两类 Oracle 分类器均在一次精细编码后完成反向和优化器更新。以三个种子的最佳检查点回放全部 Valid 和 Test 样本，逐样本确认源码位置、等长预算和存盘概率。Oracle 与 Predicted 全局向量逐元素相等。Seed 1234 另在两张 RTX 4090 上核对了索引分数与全局向量的一致性。[实际 GPU 检查记录](smoke.json)

## 研究结论

当前精细编码器能够利用更准确的检索。Oracle 在两种融合设置的每个种子上均提高整体 MCC，超长函数同时获得最大的修改保留和 MCC 增益。选择器优先保留有效修改区域，比继续修改精细编码器更直接地对应本轮发现的瓶颈。该结论来自真实修复信息驱动的特权诊断，部署时需要用当前源码识别可泛化的线索。当前 Predicted 配置继续保留 Global Fusion，移除融合的收益没有跨种子复现。
