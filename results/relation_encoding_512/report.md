# LongVul 关系感知精细编码

## 对照设计

四组沿用同一份 512 位置精细输入。每个种子重新训练 16 轮全局辅助头和 16 轮修复引导块级索引器，共用训练后冻结的索引器、32 BPE 块及 Global Mean/Max 向量。中心优先检索使用原语法关系排序及 96 位置上下文预算。四组分别从原始预训练 UniXcoder 初始化精细编码器和分类头。保留全局融合时使用零初始化线性投影的残差，Fine-only 的分类头只接收精细 CLS。各组为同一随机种子保留相同的初始化随机数消耗。

GREAT 和 Code Transformer 提供了将程序结构加入注意力打分的先例，GraphCodeBERT 使用程序数据流和图引导掩码。本实验使用条件、声明、赋值三类现有语法及词法关系，每类一个从零开始训练的标量，所有层和头共享。普通位置保留原本的注意力连接，padding 继续由原生规则屏蔽。扩展只允许预先构造的加性掩码进入 Eager 注意力，继续调用 Transformers 的原有 QK、softmax 和 Value 聚合实现。[GREAT](https://research.google/pubs/global-relational-models-of-source-code/) · [GraphCodeBERT](https://arxiv.org/abs/2009.08366) · [Code Transformer](https://arxiv.org/abs/2103.11318)

在完整源码上按现有 Tree-sitter 流程识别关系。只有两端去除缩进冗余后的正文 BPE 均完整保留时，关系才映射到精细输入位置。相同类型的无向关系及其生成的重复 Token 对去重。异类关系在同一 Token 对上时偏置相加。CLS、SEP 和 padding 的源码位置均为空。条件范围、声明和前置赋值来自语法及词法规则，语句补全继续仅用于输入保留。

PrimeVul_original Train、Valid、Test 为 8,708、1,124、1,128 个函数。精细训练为 16 轮 FP32 Eager、batch 8、学习率 2e-5、AdamW、10% 线性预热。模型以完整 Valid MCC 选模，测试阈值固定为 `p > 0.5`。跨种子对照由 Seed 42 的 Valid MCC 选定。测试模型只读取当前函数。关系覆盖和修改保留是预测后的诊断。

## 机制统计口径

关系覆盖以完整函数解析出的三类去重关系为分母，以实际进入精细编码的关系为分子。距离是两个区间之间的原始 UniXcoder BPE 数，重叠或相邻均归到 0。在异质长函数子集上，按可见关系数量或每函数最远可见关系的距离分层。配对子集指标使用两侧都符合该子集条件的完整配对。长度分组使用未截断 UniXcoder 和统一 CodeBERT BPE，配对长度为两侧中较大者。

固定检查点置零偏置时，保持编码器、分类头、全局表示、输入和掩码不变。此干预测量模型在所选检查点上对已学偏置的直接依赖。独立训练的四组用于比较训练期间可能出现的表示变化。CLS 和全局投影残差的范数在所选检查点的同一批输入上测量。

## 计算成本与验证

Standard Fusion 和 Relation-aware Fine-only 的三种子平均精细训练耗时分别为 35.90 和 38.02 分钟，峰值训练显存约为 6.45 和 6.46 GiB。Test 端到端时间分别为 36.07 和 57.31 秒，峰值推理显存约为 1.11 和 1.14 GiB。检索、打包及关系构造的合计时间为 14.73 和 34.90 秒，精细编码为 4.74 和 5.58 秒。两组都处理 4,432 个全局窗口和 1,128 个精细输入，共 2,432,962 个有效位置。关系组的额外时间主要来自完整源码关系提取及映射。

RTX 4090 真实检查覆盖 232,766 BPE 的函数。零偏置时四组 logits 的最大绝对误差为 0，三类可学习偏置均获得非零 BCE 梯度并更新。测试验证了重复关系、不同类型叠加、不完整端点、特殊位置、padding 和单次精细编码。已保存最佳检查点、逐样本预测、偏置轨迹和两种长度口径的诊断。[GPU 检查](smoke.json) · [完整结果目录](.)
