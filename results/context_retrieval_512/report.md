# LongVul 中心重要性引导的关联上下文检索

## 比较口径

Relation-based Retrieval 累加语法关系权重。Importance-guided Retrieval 对每项关系乘以对应语句的重要性，再按候选上下文累计。语句的重要性为与它重叠的已选代码块的最大索引概率。两组按相同的初始新增位置成本排序，采用相同的贪心顺序检查预算。多个语句关联到同一个源码区间时，该区间只进入候选表一次。上下文阶段结束后，剩余位置按原块分数填充。

每个种子从原始预训练 UniXcoder 的冻结非重叠窗口表示开始。重新训练 16 轮全局辅助头和 16 轮联合索引器，使用固定 32 BPE、四个查询头、128 维索引空间及权重为 1 的修复 KL。每对比较共享本轮索引器和全局表示。两个精细分类器各自从预训练 UniXcoder 初始化，采用 Global Fusion、96 个上下文位置及总计 512 个精细编码位置。精细训练使用 FP32 Eager、16 轮、batch 8、学习率 2e-5、AdamW 和 10% 线性预热。检查点按完整 Valid MCC 选择，测试正类判定为 `p > 0.5`。

统计对象为实际进入候选排序的语法关系。条件来自 Tree-sitter 的外围控制语句，声明和赋值采用词法作用域及源码顺序，语句补全沿用语法边界。这些关系描述当前实现可识别的语法和词法联系。源码距离用两个区间之间的原始 UniXcoder BPE 数计算，区间重叠或相邻归到 0。重要性分组按函数内不同分值的排序分三档，相等分值归入同档，只有一个分值时单列。

上下文阶段保留率和最终输入保留率使用完整候选区间计算。共同语句的共保留率只统计两组都完整保留来源语句且两个区间理论上能一起放入精细预算的关系，分母对两组相同。一个上下文可关联多条语句，关系覆盖按三元组计数，预算按去重后的实际 BPE 和分隔符计算。集中度使用关联到至少一个已保留候选上下文的代码块覆盖率，以及每个函数分数最高三个已选块在这些块中的占比。

PrimeVul_original 的 Train、Valid、Test 分别使用 8,708、1,124、1,128 个函数。修复标注用于 Train 索引训练及预测后的保留率评估。两种长度口径均使用未截断正文 BPE。配对指标按两侧长度较大值归组。

## 实际预算与成本

需选段的 Test 长函数平均保留 393.79 个中心 BPE，两组一致。关系排序和重要性加权分别保留 78.86 和 79.37 个上下文 BPE、26.12 和 25.65 个填充 BPE、13.22 和 13.19 个特殊位置。两组完整 Test 均执行 4,432 个全局窗口和 1,128 个精细输入，共处理 2,432,962 个有效位置。

三种子平均单次 Test 端到端耗时分别为 36.26 和 36.68 秒，其中检索和打包分别为 14.82 和 15.06 秒。峰值推理显存均值约为 1.11 和 1.12 GiB。六组各保存最佳权重、逐轮训练和逐样本预测。真实 GPU 检查完整处理了 232,766 BPE 的源码函数，核对了中心块不变、精细输入上限及两种策略的反向更新。[三种子汇总与实际成本](summary.json) · [GPU 检查](smoke.json)

在本轮匹配比较中，重要性分数能改变上下文优先级，未带来稳定的整体检测收益。正式配置保留关系排序。
